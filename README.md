# pair-wise-yf-56 网络安全事件响应作战室

## 源提示词摘要
值班人员接收告警，分析人员补充资产和影响范围，响应负责人批准隔离、封禁或恢复动作，法务和公关维护对外口径。系统展示实时事件时间线、子事件、审批、证据和责任人；高优先级动作双人确认，敏感内容按角色显示，并支持只读演示模式。

## 技术栈
Next.js 15 + TypeScript + App Router + shadcn/ui 本地组件 + Zustand + TanStack Query + React Hook Form + Zod + next-intl + date-fns + dnd-kit。

## 已实现闭环
- 主事件、子事件、处置动作和实时时间线。
- 子事件创建、动作审批、双人确认和执行状态流转。
- 角色权限控制、敏感内容遮蔽、只读演示模式。
- dnd-kit 调整处置优先级、TanStack Query 实时连接检查和 Zustand 持久化。
- **隔离核验台账（`lib/ledger/`）**：签字、执行结果、审计记录同册编号登记。
  - 三个角色（分析员 / 响应负责人 / 法务）当前版本生效签字齐全、每个受影响网段都有成功执行结果且写清执行时刻、审计记录在位，账目才确认，缺一项退回待办。
  - 敏感级别或影响范围变更即升新版本，在途签字全部作废退回待确认；离线终端按旧版本签的字重连后登记即作废。
  - 两台终端提交同一角色签字时比较签字时刻，只留最早一条，重复者保留为冲突记录；其他角色签字不受影响。
  - 断网期间签字与执行结果进本地 outbox，重连后按编号合并，重复 opId 提交幂等去重只算一次。
  - 按行落盘，写入失败后只重试没写完的条目（面板可演练注入单行失败）。

## 核验台账测试
```bash
npm run test:ledger
```
纯逻辑位于 `lib/ledger/core.ts`（编号流水/版本作废/时刻冲突/核验判定），
断网合并与写入重试位于 `lib/ledger/engine.ts`，11 条用例覆盖上述规则。
